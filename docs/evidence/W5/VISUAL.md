## Итерации снимка J1/J2 (до финального прогона)

Финальные снимки — чистые (19.3 = 0 находок). Итерации касались **конвейера снимка**
(`tools/screenshots`, входит в этот же коммит W5), а не UI:

1. **Шаги идут к именованным сессиям сценария «normal»**, у которых уже нужное
   состояние, а не «вприслонку» через `/control/state`. Причина: секция «Запрос
   разрешения» рендерится по состоянию **панели** (`pane.state === 'PROMPT'`, узел),
   а не по state сессии — принудительный `PROMPT` на сессии без PROMPT-панели показывал
   только бейдж, без секции разрешения. Теперь J2-1 — карточка `task-hold` (PROMPT-панель
   в сценарии), секция «Запрос разрешение» + кнопка «Разрешить» видны.
2. **Телефон: прокрутка к колонке состояния** (`.sc-right`). В одном вьюпорте 844 px не
   поместиться ни шапка с живым экраном, ни нижняя колонка (почему/разрешение/действия);
   шапка страницы «Сессии» (липкий топбар) и нижняя панель вкладок видны и после
   прокрутки, а смысловое ядро шага (запрос разрешения / действия очереди) — в кадре.

Состояния шагов (бейджей) из метаданных 15.1: IDLE → «Свободна», QUEUED → «В очереди»,
RUNNING → «Выполняется», HOLD → «Требует внимания».

Golden-база: `test/visual/golden/` (12 файлов W5, diff повторного прогона ≤ diff_max;
созданы при 0 находках).

## Покрытие J1/J2 (осознанное, 19.5 × 19.2)

Сценарии 19.5 требуют снимок **после каждого шага** на 1440×900 и 390×844
(`journey-J<n>-<шаг>__<размер>.png`). J1 = 4 шага, J2 = 2 шага → 6 шагов × 2 окна = 12
снимков. Каждый шаг — реальное состояние именованной сессии сценария стенда «normal»
(не заглушка): J1 `task-idle-1 → task-q1 → task-run-1 → task-idle-2`, J2
`task-hold (PROMPT-панель) → task-idle-3`. Тема — светлая (содержимое не зависит от
темы; тёмная тема покрыта на этапе W3).

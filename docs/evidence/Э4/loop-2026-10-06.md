## ⚠ НАХОДКА: фантомные ходы (пре-экзистинг, НЕ регрессия 5-го цикла)

Строка CONTROL Э4 «18/18 ходов `outcome=OK`» **нарушена**: за 18 ходов
mockcoder записывается **20–22** хода `turn` (2–4 «фантомных» хода с
`requests=0`, `started_at==ended_at`). Прогон за прогоном: **22 → 22 → 20**
(интермиттентно, зависит от тайминга). **Всё доставляется** (54/54 запроса,
0 ошибок ходов, 0 таймаутов) — фантомы не теряют работу, но ломают учёт ходов.

### Корреляция и механизм

Фантомный ход = **1 LEASE_GRANT → N LEASE_RELEASE(TURN_DONE) + N `turn`
с 0 запросами**, сессия фланирует RUNNING→IDLE (шаг ≈ toolPause mockcoder
= 500 мс). При этом реальные запросы хода фиксируются с `turn_id=0`
(не привязаны к `turn`) — см. отклонение 4 CONTROL Э4.

Причина — в done-детекции `checkTurn` (`internal/scheduler/complete.go`,
**НЕ менялся в 5-м цикле** — подтверждено `git diff`):

```go
reqCount := s.turnRequests(turn.StartedAt, sess.SID)
if reqCount > 0 {
    if !haveEnd || now.Sub(lastEnd) < s.doneQuiet() { return }  // ждать quiet
}
// reqCount == 0 → doneQuiet НЕ применяется
if pr.paneID == "" || now.Sub(pr.hashSince) < s.doneStable() { return }
s.closeTurn(sess, turn, now)
```

Когда сессия **долго ждала в очереди** (раунд 2: до ~12 с), её панель IDLE и
хеш стабилен (`hashSince` ≥ `done_stable_sec`). В момент выдачи слота
(DISPATCH + Enter) панель ещё не перерисована в BUSY (снимок узла с
`scan_interval_sec=1`), а запросов у только-что открытого хода пока 0 →
условие `reqCount==0 → doneQuiet не нужен` + IDLE + хеш стабилен →
`closeTurn` **сразу закрывает пустой ход** (0 запросов), аренда снимается
`TURN_DONE`, сессия → IDLE, пока mockcoder ещё запускает ход.

### Диагностика: фикс границы тика — ЗАЩИТНЫЙ (не источник фантомов)

| Прогон | фикс `setCooldown`→`AfterFunc` | ходы | max аренд/сервер | нарушений |
|---|---|---|---|---|
| с фиксом (`ff993967`) | вкл | 22 / 20 | **1** | **0** |
| без фикса (откат `AfterFunc`) | выкл | 22 | **2** | **2** (server a, t≈51 с) |

- **Фантомные ходы есть и с фиксом, и без** → это **не от фикса**, а пре-
  экзистинг в done-детекции (base `dfb70b3`).
- **Без фикса появляется double-lease** (1-слотовый сервер `a` на ~0.5 с
  держит 2 активные аренды): преждевременное снятие аренды освобождает слот,
  пока кодер ещё работает → слот выдаётся второй сессии.
- **С фиксом double-lease нет** (max=1): точное снятие COOLDOWN в
  `released_at+cooldown` убирает окно, в котором слот «двойно» считается
  свободным.

**Вывод:** фикс границы тика (уже в бинарнике) **снимает критическое
последствие** (double-lease) пре-экзистинг-бага, но **сам баг**
(преждевременное закрытие пустого хода) остаётся и может проявляться иначе
(в пр.) — при другой фазе тика/скана узла.

## Рекомендация

1. **Деплой (п.4) — только с фиксом границы тика** (`ff993967`): без него
   e2e даёт double-lease (нарушение критерия 1).
2. **Пре-экзистинг-баг done-детекции** (преждевременное закрытие хода при
   `reqCount==0` и стабильной IDLE-панели после долгого ожидания в очереди)
   стоит исправить отдельным пунктом, чтобы гарантировать «ход не закрывается
   до первого запроса/подтверждения BUSY». Вариант фикса: в `checkTurn` не
   закрывать ход, если он открыт **менее** `done_quiet_sec` **и** у сессии ещё
   нет ни одного запроса с момента DISPATCH (окно «только что выдан, панель
   ещё не BUSY»). Пока не исправлено — риск преждевременного IDLE у сессий,
   долго ждавших в очереди (в т.ч. реальный qwen с длиннее «стартом»).

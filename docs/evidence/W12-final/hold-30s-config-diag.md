## Вывод

1. **Шлюз НЕ закончил удержание по hold_max_sec:** hold_max_sec=3600 (дефолт, без переопределения), удержание не кончается на 30с.
2. **Ответ шлюза — не 503:** request 213 = CLIENT_GONE (клиент отключился), не HOLD_TIMEOUT. Путь hold-timeout (`heldToResume`→`writeNoSlot` 503) не создаёт request-запись; CLIENT_GONE — только из `clientGone` (ctx.Done клиента).
3. **Ретрай не через 30с:** ретрай пришёл через 60.7с после обрыва, не совпадает с Retry-After: 30.
4. **Метрики gateway не существуют** (aqm_gateway_requests_total / aqm_gateway_hold_seconds нет в коде).

## По п.3: «Ответ шлюза не 503 → прислать п.1–2 и остановиться»

Ответ шлюза не 503 (hold_max_sec=3600, CLIENT_GONE). **Останавливаюсь** с п.1–2.

## Что НЕ подтверждено

- Гипотеза «шлюз закончил удержание и ответил 503 + Retry-After: 30» — **не подтверждена** (hold_max_sec=3600, ответ не 503, ретрай через 60.7с).
- Причина 30s client_gone (клиент отключился через 30с удержания) остаётся неисследованной: журнал шлюза утрачен, метрик нет.

## Следующий шаг

Причина 30s client_gone (почему клиент отключился через 30с) требует:
- persistent-лога координатора (п.4) — чтобы видеть строки шлюза при обрыве;
